每一段做了什么 ^dethdr01

虚线框是一个阶段，顺序与上方各列一致。颜色同上：橙 = TF-A，黄 = bootloader，蓝 = 内核，紫 = 硬件描述。 ^detsub01

BootROM / BL1：信任根（片上 ROM，在 SRAM 里运行） ^modd0ttl

- 上电后 CPU 从固定的复位地址取指，此时只有片上 ROM 和 SRAM
- 只做最少的初始化：异常向量、SRAM 里的栈、启动介质控制器
- 从 flash / eMMC 等启动介质读出 BL2，放进 SRAM
- 校验 BL2 的签名：ROM 不可改写，所以它是安全启动的信任根
- 有的平台 BootROM 就是 BL1，有的在 ROM 之后另有一级 BL1 ^modd0txt

BL2：先把 DRAM 准备好，再把后面的镜像搬进来 ^modd1ttl

- 初始化 DDR 控制器并做训练（时序校准），DRAM 从此可用
- 按镜像清单加载 BL31、BL32（可选）、BL33 到各自地址
- 逐个校验镜像（可信启动的证书链）
- 把各镜像的入口地址和参数交给 BL31
- 完成后退出，不常驻 ^modd1txt

BL31（+ 可选 BL32）：常驻 EL3 的运行时固件 ^modd2ttl

- 配置安全状态：哪些资源只给安全世界，低 EL 能否使用某些 CPU 特性
  （没放开的特性，内核一访问就陷入 EL3，表现为异常或挂住）
- 初始化 GIC 的安全部分；通常也在固件阶段写好定时器频率 CNTFRQ
- 注册运行时服务：PSCI（开关核、挂起、重启关机）、SDEI 等
- 可选启动 BL32 安全 OS（如 OP-TEE）
- 切到非安全 EL2 跳 BL33，自己常驻，等待内核的 SMC 调用 ^modd2txt

BL33：两条把内核送到入口的路径（最终都满足同一份入口要求） ^modd3ttl

路径 A：U-Boot 直接启动（booti） ^modd3sa1

- 初始化自己的驱动：串口、存储、网络
- 按 bootcmd 加载 Image、DTB、initrd 到内存
- 修补 DTB：写入实际内存大小、bootargs、
  initrd 位置、随机种子（KASLR 用）
- 关 MMU、clean cache，x0 = DTB 地址，跳内核 ^modd3ba1

路径 B：UEFI → EFI stub ^modd3sb1

- UEFI 固件（如 EDK2）初始化平台，提供 Boot Services
  （只在启动期间可用）和 Runtime Services（留给 OS）
- 把 Image 当 EFI 应用加载：Image 带 PE 头、内含 EFI stub
  （可经 GRUB 等中转）
- EFI stub 在 UEFI 里运行：取命令行、加载 initrd、
  必要时搬移内核、向固件要随机种子
- 生成一个小 DTB，只放 EFI 系统表、内存表位置和命令行
- 调用 ExitBootServices 结束固件接管，按同一协议跳内核 ^modd3bb1

两个独立的选择 ^modaxttl

- 启动接口：booti 直接跳转 ／ UEFI（EFI stub）
- 硬件描述：DT ／ ACPI
- arm64 上 ACPI 只能经 UEFI 传入
  （内核从 EFI 配置表找到 ACPI 根指针）
- 常见组合：
  嵌入式：booti + DT
  服务器（SBSA / SystemReady SR）：UEFI + ACPI
  UEFI + DT 也可（如 U-Boot 的 bootefi） ^modaxtxt

ACPI 表各管什么（对应 DT 里的哪部分） ^modacttl

- MADT ↔ cpus + GIC 节点：有哪些 CPU、中断控制器在哪
- GTDT ↔ timer 节点：架构定时器的中断
- SPCR ↔ chosen/stdout-path：串口在哪（earlycon 可直接用）
- FADT ↔ psci 节点：PSCI 走 SMC 还是 HVC
- MCFG ↔ PCIe host 节点：配置空间（ECAM）地址
- IORT ↔ iommu-map / msi-map：设备到 SMMU、ITS 的连接
- PPTT ↔ cpu-map：CPU 拓扑和 cache 层次
- SRAT / SLIT ↔ numa-node-id / distance-map：NUMA
- DSDT / SSDT ↔ 其余设备节点（AML 字节码，可带方法） ^modactxt

head.S：从“MMU 关”走到能跑 C 代码 ^modd4ttl

- 记下进入时的状态：MMU 是否开着、x0~x3（DTB 地址等）
- 建恒等映射页表（虚拟地址 = 物理地址），保证开 MMU 那一刻取指不断
- 配置 EL2：决定内核留在 EL2（VHE）还是降到 EL1
- 设置内存属性、页表格式，然后打开 MMU
- 把内核映射到最终虚拟地址；开 KASLR 时在这里随机化并重定位
  （这一步会先读命令行里少数早期开关，如 nokaslr、CPU 特性屏蔽）
- 装好异常向量表和初始栈，进入 C 代码 start_kernel ^modd4txt

setup_arch：start_kernel 最先调用的架构初始化 ^modd5ttl

- 早期访问手段：fixmap、early_ioremap，页表建全前临时映射 DTB 和寄存器
- 读硬件描述：校验 DTB（无效就停在这里），取出内存范围、命令行、板型
- 早期参数：earlycon 在这里起来（它靠 fixmap 映射 UART，所以不可能更早）
- 打开 SError / Debug 异常：从此硬件错误能报出来
- UEFI 启动时：读 EFI 内存表，准备 Runtime Services
- 内存三步：登记内存，预留内核 / DTB / initrd / reserved-memory
            → 建完整内核页表和线性映射
            → 划分 zone、NUMA，预留 CMA、crashkernel
- 设备描述：ACPI 解析表；否则把 DTB 展开成运行时设备树
- 多核准备：确定 PSCI 走 SMC 还是 HVC，从 DT / MADT 枚举 CPU（从核还没启动）
- 检查启动协议：x1~x3 不为 0 会告警 ^modd5txt

start_kernel 其余部分：只有主核，还没有驱动 ^modd6ttl

- 设置每 CPU 数据区，最终解析命令行
- 内存分配器就位：buddy + slab 接替 memblock
- 异常处理、调度器、RCU、workqueue 的基础结构
- 初始化 GIC 和架构定时器，然后第一次打开中断
- console 框架就位（真正的串口驱动还没 probe）
- 其余核心设施：进程 / 文件系统缓存、cgroup、ACPI 子系统等
- 最后创建 PID 1（kernel_init）和 kthreadd，主核进入 idle ^modd6txt

smp_init：拉起从核（在 kernel_init 线程里） ^modd7ttl

- 按 DT / MADT 枚举到的 CPU 逐个启动
- 每个从核：内核调 PSCI CPU_ON → BL31 让它从内核的从核入口开始执行
  （DT 也可用 spin-table：从核轮询一个地址，内核写入入口后放行）
- 从核走一遍精简的入口流程：定 EL、开 MMU（用现成的内核页表）、
  初始化本核的 GIC 接口和定时器
- 检查各核特性是否一致，缺少必需特性的核会被拒绝上线
- 全部上线后建立调度拓扑 ^modd7txt

initcall：驱动初始化 ^modd8ttl

- 按级别依次执行内置子系统和驱动的初始化函数
- 总线、驱动注册后，按 DT 节点 / ACPI 设备匹配并 probe
- 串口驱动 probe 后注册正式 console，earlycon 随之退出
- 存储、网络、PCIe 枚举都在这一阶段
- 依赖还没就绪的设备推迟 probe（deferred probe），之后重试
- initramfs 在后台解开 ^modd8txt

挂根文件系统，执行 /init ^modd9ttl

- 有 initramfs 且其中有 /init：直接运行它，由它负责挂真正的根
- 否则按 root= 挂载根设备（rootwait 会等设备出现）
- 释放 __init 段内存，执行 /init（或 /sbin/init），进入用户态 PID 1
- 典型失败：VFS: Unable to mount root fs、No working init found ^modd9txt

出问题时：用这张图定位 ^pahdr001

1. 看最后一行输出落在哪一列
2. 往右找第一样还没出现的东西：它就是嫌疑

① bootloader 最后一行之后没输出（黑区）
   对照入口要求；DTB 无效也会停在这里；
   查 earlycon= 和 UART 地址；调试器看 PC、读 __log_buf
② earlycon 有，正式 console 没有
   串口驱动没 probe：DT 节点 / ACPI 设备、clock、console=
③ 只起来一个核
   沿 PSCI 虚线：enable-method / MADT、BL31 CPU_ON、特性不一致
④ 卡在 timer / 中断初始化
   入口要求没做完：CNTFRQ、ICC_SRE_EL3/EL2
⑤ setup_arch 里挂住，或早期内存异常
   内存描述和实际不符：memory 节点 / EFI 内存表、reserved-memory
⑥ 挂根失败
   根设备驱动没 probe、root= 写错、initramfs 里没有 /init ^pabody01

交接点的入口要求 ^pbhdr001

x0 = DTB 物理地址，x1~x3 = 0
PSTATE.DAIF 全部屏蔽
非安全态，EL2（推荐）或 EL1
MMU 关；镜像所在内存已 clean 到 PoC
CNTFRQ 已设好，各核 CNTVOFF 一致
GICv3：ICC_SRE_EL3/EL2 已打开
SVE、SME 等：EL3/EL2 的陷入位已放开 ^codetxt1

主线 v7.0：Documentation/arch/arm64/booting.rst ^pbsrc001

固件少做一项，内核入口不报错，
而是第一次用到它时才挂：现象离原因很远（①④） ^pbnote01

慢环境（仿真器 / FPGA）：先测再裁 ^pchdr001

1. 先测：printk.time=1、initcall_debug，
   看时间花在哪一列
2. 串口打印本身就慢：调低 loglevel 或 quiet
3. 省掉 bootloader：前级直接把 Image、DTB
   放进内存再跳内核（见 boot-flow.md）
4. 裁 config；用 initramfs 代替根盘

2~4 为经验做法，收益要在自家平台实测 ^pcbody01
