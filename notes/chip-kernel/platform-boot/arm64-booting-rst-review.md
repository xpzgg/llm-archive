# Booting AArch64 Linux：复习笔记

> 原文：<https://docs.kernel.org/arch/arm64/booting.html>。配套图：[arm64-boot-bringup.excalidraw.md](arm64-boot-bringup.excalidraw.md)。
>
> 标 ⚠ 的是第一遍读时理解不到位的地方，复习时重点看。

## 这篇文档是什么

它是 arm64 内核的**入口协议**：规定内核之前的所有软件（文档统称 bootloader）跳进内核前必须做到哪些事。对内核侧来说，它就是**定界的边界**：挂住的点用到的是这里的某一项，先请固件对照核对；不是，再查内核自己。

沿用 32 位 ARM 启动文档的写法，但做了简化：硬件描述只有 DTB 一种（地址放 x0），镜像不压缩、也不带解压代码。

## bootloader 的职责

1. **初始化 RAM**：让内存能读写，即 DDR 初始化和训练，通常由 BL2 做。内存范围通过 DTB 或 EFI 内存表告诉内核。
2. **准备硬件描述**：DTB，或经 UEFI 传入 ACPI。
3. **解压内核**：如果 Image 是压缩存放的，由 bootloader 解压。
4. **按要求跳进内核**：见下面"入口要求"。

（Realm 相关的句子属于机密计算，普通启动可以跳过。）

## 镜像头（64 字节）

作用：Image 是内存镜像，没有 ELF 那样的格式信息。这个头告诉 bootloader：是不是 arm64 内核（magic）、放在哪（text_offset）、留多大（image_size）、从哪执行（code0/code1）。它还让同一个 Image 既能被 booti 直接启动，也能被 UEFI 当作 PE 程序加载（code0 的编码以 "MZ" 开头，res5 指向 PE 头）。

- ⚠ **image_size 不是文件大小**，是内核运行时总共占用的内存，包括 bss。bss 不存进文件，但链接时大小就已确定（到 `_end` 为止），由链接器写进头里。bootloader 不能把 DTB、initrd 放进这个范围，否则内核清零 bss 时会把它们抹掉。
- **flags bit 3**：Image 能不能放在任意物理位置。现在的内核都是 1，只要求在 48 位物理地址范围内。老内核用不了镜像"下方"（低地址）的内存，所以要求紧贴 DRAM 开头放。

## 内存相关的约束

- ⚠ **initrd 的 32GB 范围**：内核和 initrd 必须一起落在一块"1GB 对齐、不超过 32GB"的**物理地址**范围里，这块范围的位置随意，不是指 0~32GB。大小的限制来自虚拟地址一侧：最小配置下，线性映射只能装下约 32GB 物理内存。内核挑线性映射覆盖哪段内存时，一定会包含自己，所以 initrd 离内核足够近就一定能访问到。违反时内核会打出 `initrd not fully accessible via the linear mapping` 警告，丢弃 initrd，之后多半挂根失败。
- **没标保留的内存，内核就当作可用**，包括镜像下方的内存。固件常驻的内存（BL31、OP-TEE 等）必须标成保留。漏标时启动不报错，之后才出现离原因很远的故障。这是高概率问题，详见阅读清单第 4 节的笔记。

## 入口要求

- 寄存器：x0 = DTB 物理地址，x1~x3 = 0。
- 中断：DAIF 全部屏蔽。
- EL：非安全态，EL2（推荐）或 EL1。从 EL2 进入，内核才能留在 EL2 或在 EL2 留好自己的代码，KVM 依赖这一点；从 EL1 进入就再也拿不回 EL2。
- MMU 和 cache：MMU 关，镜像所在的内存已 clean 到 PoC（MMU 关着时访存不经过 cache，内核只能读到 DRAM 里的内容）。

### 架构定时器

- **CNTFRQ**：写入计数器频率。只有最高 EL 能写，内核写不了。FPGA 和仿真器上常见漏写或写错。
- **CNTVOFF**：各核一致，否则各核时间不一致。
- **EL1PCTEN**：从 EL1 进入时，EL2 要允许 EL1 读物理计数器。

### 一致性

所有核进内核前必须已在同一个一致性域里：各核看到的内存是同一份，维护操作（作废 TLB、清理 cache）能广播到每颗核。怎么加入一致性域由具体实现定义，由固件负责。漏做的现象：单核正常，多核随机出错。

- ⚠ **一致性不等于核间通信**。核间发消息（IPI）走 GIC 的软件中断，和一致性无关。
- ⚠ **ARM64 的维护操作靠硬件广播，不靠 IPI**。带 IS 后缀的 TLBI 指令，以及 DC / IC 指令，会经互连总线送到所有核。用 IPI 让各核自己刷 TLB（TLB shootdown）是 x86 的做法。
- ⚠ **cache 和 TLB**：cache 缓存内容（数据、指令），TLB 缓存地址翻译。普通数据变化不用刷 TLB，只有页表变了才刷。顺序：写页表项 → 屏障 → TLBI → 屏障。改一个正在用的映射，要先清成无效、刷 TLB，再写新值（break-before-make）。
- ⚠ **页表写入也先进 cache**。ARM64 的硬件查页表可以配置成和 cache 一致，所以不用写回内存。两个例外：MMU 关着的时候；以及不和 CPU cache 保持一致的设备。
- ⚠ **SMMU 和外设不是天生看不到 cache**。能不能看到，由芯片把设备接到哪种总线端口决定：IO 一致的设备，读写时会侦听 CPU cache；非一致的设备，要由软件手动维护 cache。内核通过 DT 的 `dma-coherent` 或 ACPI 的 IORT 得知是哪种，描述错了就会出现偶发的 DMA 数据错误。

### 系统寄存器

- 内核所在 EL 及以下的可写寄存器，都要由更高 EL 初始化。复位值是 UNKNOWN，不初始化的话，换板子或换核，行为就可能不同。
- ⚠ **寄存器命名的规律**：每个 EL"管自己"的寄存器各有一份（SCTLR、TTBR、VBAR、ESR 等 `_ELx`）；只属于某一级的寄存器只有一份（HCR_EL2、SCR_EL3 等）；后缀表示**最低哪一级能访问**，不一定是属于哪一级（比如 CNTFRQ_EL0 用户态能读，但只有最高 EL 能写）。
- **SCR_EL3.FIQ**：决定 FIQ 送到 EL3 还是留给内核。要求各核一致，运行中不变。
- **SCR_EL3.HCE**：从 EL2 进入时必须为 1，否则 HVC 指令非法，启动早期就挂。
- **按特性列的一长串**：都是同一个套路，即"CPU 有某特性，比内核高的 EL 不能拦住它"。有 EL3 时，EL3 要放开；从 EL1 进入时，EL2 也要放开。另外几项值要求各核一致：SVE / SME 的向量长度、GICv3 的 PMHE。GIC 的模式也要和 DT / ACPI 里描述的一致。具体怎么配是固件的事；内核侧要记住的是：漏放开时，故障出现在**第一次用到这个特性**的时候，可以按挂住的位置反推是哪一类。

## 多核

- 上面所有要求，**每颗 CPU 都要满足**；所有 CPU 必须从**同一个 EL** 进入。
- 主核直接跳到镜像第一条指令；DTB 里每个 cpu 节点要有 `enable-method`。
- 从核两种拉起方式：
  - **spin-table**：从核在保留内存里循环读 `cpu-release-addr`。主核写入入口地址，再 `sev` 唤醒它，从核自己跳过去。不能给核断电。
  - **PSCI**：内核调用 CPU_ON（通常走 SMC 进 EL3），由 BL31 给核上电，让它从入口开始执行。服务器和 ACPI 平台基本都用它。
- ⚠ **"从核在内核之外"** 指的是从核没在执行内核代码，也不在内核管理的内存里（断电，或停在固件、bootloader 的保留区里），跟它处于哪个 EL 无关。spin-table 也不是主核给从核"发指令"，而是通过共享内存放行。
- 从核进入内核时，x0~x3 都必须是 0。
