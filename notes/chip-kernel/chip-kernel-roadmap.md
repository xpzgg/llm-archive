# 芯片内核能力路线图：软芯协同 + 软硬协同

> 用途：作为长期学习路线。每学完一项，更新"状态"列，并链接到对应的笔记或图。
> 建立于 2026-10-17。

## 为什么要有这张图

我的工作是芯片公司的内核：为芯片方案和原型构建内核，并用它验证芯片的各种软芯 / 软硬协同特性（MPAM、TLBID 只是其中两个例子），覆盖回片前（仿真器、FPGA、模型上的开发验证）和回片后（bring-up、稳定性）。

这类工作需要两种能力：

- **软芯协同**：软件和处理器芯片本身的配合，包括 CPU 核、cache、MMU、多核、固件。
- **软硬协同**：软件和外设的配合，包括中断、DMA、IOMMU、设备队列。

以前是这里学一点、那里学一点，不成体系。这张图把需要的能力拆成 21 项，分成四层：

| 层 | 内容 |
|---|---|
| 基础层 | 两边共用的底层规则 |
| 软芯协同 | 软件和 CPU / SoC 的配合 |
| 软硬协同 | 软件和外设的配合 |
| 特性工作流 | 一个特性在内核里从发现、使能到验证的全过程，也就是日常工作本身 |

前三层讲**机制怎么工作**，是理解一个特性的基础。第四层讲**一个特性怎么落地**。

★ 表示核心、优先掌握。状态取值：已学 / 部分 / 未开始。

## 特性工作流（芯片内核的日常工作）

| #   | 机制              | 回答什么问题                                                                                                  | 优先级            | 状态                                                                   |
| --- | --------------- | ------------------------------------------------------------------------------------------------------- | -------------- | -------------------------------------------------------------------- |
| 15  | 特性发现与使能         | 内核怎么读 ID 寄存器（`ID_AA64*_EL1`）判断 CPU 支持哪些特性；cpufeature 框架怎么在所有核之间取交集、替换代码路径（alternatives）、把能力告诉用户态（hwcap） | ★ 每个新特性的第一步    | 部分（见 [FEAT_NMI / ALLINT 问题](../linux-kernel/interrupt/arm64-feat-nmi-allint-bug.md)） |
| 16  | 芯片勘误与规避（errata） | 芯片有 bug 时，内核怎么只在受影响的型号上打开规避代码                                                                           | ★ 回片后几乎必用      | 未开始                                                                  |
| 17  | 资源划分与 QoS       | 怎么给不同任务划分 cache 容量和内存带宽，并监控实际用量：MPAM，内核里对应 resctrl                                                      | ★              | 未开始                                                                  |
| 18  | 调试与追踪           | 不打断程序运行，怎么看到 CPU 实际做了什么：CoreSight、ETE / TRBE（指令追踪）、SPE（访存采样）、PMU                                        | ★ 验证和定位问题的主要手段 | 未开始                                                                  |
| 19  | RAS 与错误上报       | 硬件出错（ECC 错误、总线错误）时怎么通知内核、怎么处理：RAS 扩展、SError、SDEI、APEI                                                   | 重要（回片后的稳定性）    | 部分（见 [SDEI](../linux-kernel/interrupt/arm-sdei.md)）                                  |
| 20  | 平台启动与 bring-up  | 从固件（TF-A、UEFI / U-Boot）到内核的交接；最早期的打印（earlycon）；在仿真器、FPGA 这种很慢的环境里怎么裁剪内核、加快启动                            | ★ 回片前和回片后都要做   | 部分（见 [启动与 bring-up 图](platform-boot/arm64-boot-bringup.excalidraw.md)、[启动流程](platform-boot/boot-flow.md)、[启动阶段的内存初始化](../linux-kernel/mm/boot-mem-init.md)） |
| 21  | 验证方法            | 怎么写特性测试：kselftest、kunit、kvm-unit-tests，以及自己写的测试模块；怎么设计覆盖边界情况的用例                                         | 重要（工作的产出形式）    | 未开始                                                                  |

## 学一个新特性的固定路径

工作中每遇到一个新特性，都按这六步走一遍，并把结果写成笔记：

1. **规范**：Arm ARM 或相关规范里怎么定义，要解决什么问题。
2. **发现**：用哪个 ID 寄存器、哪个字段判断芯片支持它（15）。
3. **使能**：内核要写哪些寄存器、在启动的哪个阶段写，有没有固件参与（7、20）。
4. **使用**：内核或用户态怎么用它，接口是什么。
5. **验证**：怎么写测试证明它工作正常，覆盖哪些边界情况（21）。
6. **定位**：出问题时用什么手段看到硬件的实际行为（18），是不是芯片 bug、要不要加规避（16）。

## 建议顺序

| 阶段  | 内容                                                                                                                                                 | 理由                                                               |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| A   | 4 MMU / TLB + 11 IOMMU L2；1、2、5 在其中遇到时讲透                                                                                                           | IOMMU 就是"给设备用的 MMU"，两者一起学最省力；TLBID 也落在这里                         |
| B   | 15 特性发现与使能，再挑一个手头正在做的特性，按"固定路径"完整走一遍（例如 MPAM）                                                                                                      | 用真实工作检验方法；MPAM 这类内核侧还在演进的特性，也适合作为社区贡献的切入点（计划 2026 年 11 月起集中投入社区） |
| C   | 12 描述符环 + doorbell（选 virtio 或 NVMe 做样本，按调用图规则画出"提交 → doorbell → 完成中断"路径） | 把 1、2、10、11 串起来，检验软硬协同是否真正理解                                     |
| D   | 18 调试与追踪、16 errata、20 bring-up、19 RAS                                                                                                              | 直接对应回片前后的验证和定位工作                                                 |
| E   | 补深 3、6、7、8，之后再看 13、14                                                                                                                              | 13、14 依赖前面全部内容；13 是 AI 加速器（GPU / NPU）的关键                         |

## 和长期方向的关系

- **内核社区**：RCU 主要依赖 2；IOMMU 依赖 4、11、13；PCIe 依赖 1、9；MPAM 依赖 15、17。
- **AI Infra**：GPU 驱动和 CUDA 运行时几乎用到 11～13 的全部内容（kernel launch 就是写命令环再写一次 doorbell）；性能调优离不开 5 和 8；多机多卡通信（NCCL）离不开 1、6、11。
