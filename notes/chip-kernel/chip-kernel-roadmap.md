# 芯片内核能力路线图：软芯协同 + 软硬协同

> 用途：作为长期学习路线。每学完一项，更新"状态"列，并链接到对应的笔记或图。
> 建立于 2026-10-17；2026-11-21 按硬件层次重新划分。

## 为什么要有这张图

我的工作是芯片公司的内核：为芯片方案和原型构建内核，并用它验证芯片的各种软芯 / 软硬协同特性（MPAM、TLBID 只是其中两个例子），覆盖回片前（仿真器、FPGA、模型上的开发验证）和回片后（bring-up、稳定性）。目标是把 ARM 架构相关的底层能力补齐，无论之后做 Linux 内核，还是 GPU / NPU 驱动开发，都有扎实的基础。

时间有限，所以只求把最重要的能力快速建起来：三星的项优先学透，不标星的大致看懂概念即可，其余专题（例如各种安全扩展）工作中碰到再学。

以前是这里学一点、那里学一点，不成体系。这张图按**硬件结构从核往外**分层：先是 CPU 核本身，然后是一次访存在核内怎么处理，再是请求出核以后怎么在互联上传输，接着是中断和时间、外设，最后是整个平台怎么启动和管理。每层建立在前一层之上。

| 层          | 回答什么问题                              |
| ---------- | ----------------------------------- |
| 0 SoC 硬件全景 | 整颗芯片由哪些部件组成，哪些在核内、哪些在 cluster、哪些在核外 |
| 1 处理器核     | 核怎么执行指令、怎么切换特权级                     |
| 2 访存       | 一次访问去哪里、能不能缓存、别的核什么时候看到             |
| 3 互联与带宽    | 请求出核以后怎么传输；多核、多 cluster 怎么组织；带宽怎么分配 |
| 4 中断与时间    | 怎么通知 CPU 有事发生；怎么计时、怎么在指定时刻触发事件      |
| 5 设备 I/O   | 软件和设备怎么交换数据，设备怎么访问内存                |
| 6 平台与系统控制  | 系统怎么启动、开关核、进入低功耗；内核怎么和固件配合          |
| 7 架构扩展     | 贯穿各层的扩展：虚拟化、性能监控、调试追踪、RAS           |
| 应用层：特性工作流  | 用前面的机制把一个具体特性在内核里落地：发现、使能、验证、定位     |

1～3 层和第 6 层主要是**软芯协同**（软件和 CPU / SoC 的配合），4～5 层主要是**软硬协同**（软件和外设的配合）。1～7 层讲**机制怎么工作**，应用层讲**一个特性怎么落地**。

同一个机制可能在两层都出现，各层看的角度不同。例如写一个设备寄存器：第 2 层看它的内存属性和顺序要求，第 3 层看它走什么路径、什么时候真正到达设备。

Linux 内核自身的软件机制（锁、RCU、调度、内存分配）和 GPU / NPU 驱动框架（DRM / accel、dma-buf）不在这张图里，归 `notes/linux-kernel/` 那条线。

**重要度**：

| 标记 | 含义 |
|---|---|
| ★★★ | 核心，必须学透，找工作前完成 |
| ★★ | 重要，要能讲清机制 |
| ★ | 先建立概念，工作需要时再深入 |
| 不标星 | 大致看一下，知道是什么、解决什么问题即可 |

状态取值：已学 / 部分 / 未开始。

## 学一个新特性的固定路径

工作中每遇到一个新特性，都按这六步走一遍，并把结果写成笔记：

1. **规范**：Arm ARM 或相关规范里怎么定义，要解决什么问题。
2. **发现**：用哪个 ID 寄存器、哪个字段判断芯片支持它（28）。
3. **使能**：内核要写哪些寄存器、在启动的哪个阶段写，有没有固件参与（20、21）。
4. **使用**：内核或用户态怎么用它，接口是什么。
5. **验证**：怎么写测试证明它工作正常，覆盖哪些边界情况（32）。
6. **定位**：出问题时用什么手段看到硬件的实际行为（25、26），是不是芯片 bug、要不要加规避（29）。

## 建议顺序

主线是先机制、后应用，机制部分按层从里往外走，每层内部按编号顺序学。每层先学三星项；不标星的项只需大致看一下，可以放在本层最后。

| 阶段 | 内容 | 理由 |
| --- | --- | --- |
| 0 | 0 SoC 硬件全景 | 先有全局图，后面学到的每个部件都有位置可放 |
| A | 1 处理器核：2 异常模型为主，1 指令集快速过一遍，再学 3；4 大致看一下 | 中断、系统调用、缺页、调用固件、虚拟化本质上都是异常，这是后面所有内容的入口 |
| B | 2 访存：5 → 6 → 7 → 8 | 重点层，花最多时间。DMA、SMMU、设备内存、RCU 都建立在这层上 |
| C | 3 互联与带宽：9 → 10 → 11 | 访存出了核就是互联，紧接着学最顺。学到概念层即可，不必深入协议细节 |
| D | 4 中断与时间：12 回顾，13 新学 | 中断已学过，对照架构再过一遍；Timer 和中断在"定时器中断"这里相连 |
| E | 5 设备 I/O：14 → 15 → 16 → 17 → 18 → 19 | 把 2～4 层串起来，检验软硬协同是否真正理解；GPU / NPU 工作最看重这一层 |
| F | 6 平台与系统控制：20 → 21 → 22 → 23 | 把前面所有部件放回整机：怎么启动、怎么开关核、怎么管理电源 |
| G | 7 架构扩展：25 → 26 → 27 → 24 | 依赖前面全部内容；25、26 是日常定位问题的手段，先学；24 虚拟化最后 |

应用层随主线穿插：

- 28 特性发现：A 阶段学完就能做。
- 30 MPAM：C 阶段之后学概念和规范，作为第一次完整走"固定路径"的特性；E 阶段学完 14、17 之后再看内核驱动和 resctrl。
- 31 bring-up：F 阶段学完 21 之后。工作需要时，F 阶段的启动内容也可以提前。

## 和长期方向的关系

- **内核社区**：RCU 主要依赖 8；IOMMU 依赖 5、17、19；PCIe 依赖 9、15；MPAM 依赖 7、11、30。
- **内核岗位**：重点是 1、2、4、6 层和应用层。
- **GPU / NPU 岗位**：重点是 2、5 层。GPU 驱动和 CUDA 运行时几乎用到 16～19 的全部内容（kernel launch 就是写命令环再写一次 doorbell）；性能调优离不开 3、7、25，以及 11 的带宽概念；多机多卡通信（NCCL）离不开 9、10、16。
