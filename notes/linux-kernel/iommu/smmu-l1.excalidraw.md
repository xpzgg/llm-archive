5 为什么这样设计：把每一层拿掉，看会出什么问题 ^s5hdr001

拿掉它：所有设备共用一套映射，
网卡能碰的 GPU 也能碰，

SubstreamID → CD ^s5n1txt0

拿掉它：一个设备只有一套页表，

按 SubstreamID 选出

页表（与 CPU 同格式） ^s5n2txt0

所以：按页翻译并带读写权限；

ATS 让设备也缓存了翻译 → 解除映射时还要多发 CMD_ATC_INV

网卡、NVMe 这类高频小 IO 时 CPU 开销明显 ^s6k1Ltxt

lazy 模式（iommu.strict=0）：先攒一批，再统一作废 TLB ^s6k1Rtxt

失效前的短窗口里，设备仍可能用旧翻译访问已释放的页：
用一点隔离换吞吐（strict 模式则每次立刻作废） ^s6k1Ptxt

表和页表占内存；每次映射都要分配 IOVA、写页表 ^s6k2Ltxt

passthrough（iommu.passthrough=1）：STE 设为 BYPASS，
设备直接用 PA ^s6k2Rtxt

等于回到第 1 节：没有隔离，也没有地址重映射；
只适合可信设备、追求极限带宽的场景 ^s6k2Ptxt
